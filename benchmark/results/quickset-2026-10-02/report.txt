Detection and false positives are reported separately and never
combined into a single score. A scanner that flags every file has
perfect detection, and one that flags nothing has a perfect false
positive rate; only the pair means anything.

Each scanner's main row is its strict threshold: only the tier its
author calls actionable. The '+unknown' row adds that tool's unknown
bucket (picklescan's suspicious, modelaudit's warning, fickling's
SUSPICIOUS, hayward's INFO), the analogue of not-flagged for a
human triager. Report both thresholds or neither: scoring one tool
at its top tier while counting another's unknown tier is the
specific unfairness this table exists to avoid. Run with --verbose
to see each scanner's own verdict string per case.

Detection is given twice. 'Of files read' asks whether a scanner
finds the payload when it opens the file. 'Of corpus' asks what
it catches from everything handed to it, counting the files it
never read as misses. The second is what an operator gets, and
the two diverge sharply for tools with low coverage: a scanner
that reads a sixth of the corpus can score well on the first
column while catching very little.

Coverage is the share of files the scanner returned any verdict
on. Errored files (parse failures, crashes, zero-file scans) are
excluded from both numerators and denominators alike: a tool that
never read the file has no verdict to its name.

Cases marked KNOWN MISS are detected by nothing here, including
the scanner this project is written alongside. They are carried on
purpose: a corpus holding only cases its author passes is a corpus
that flatters its author. A case losing that mark because someone
fixed it is the most useful thing this benchmark can report.
